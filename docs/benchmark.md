# Локальные измерения — 17 октября 2026

## Desk temporal benchmark — 18 октября 2026

Новый двухпроходный режим сравнен с legacy на **одном сгенерированном MOV**,
7 s, 160×120, 140 исходных кадров, 20 FPS. Три перекрывающиеся synthetic ROI
активированы только для профиля `synthetic-only`. Два движения квадрата:
1.5–2.25 и 4.5–5.25 s; короткий импульс 3.40–3.45 s специально находится между
обзорными samples. Это не банковская запись и не объекты наличности/люди.

Команда: `python -m scripts.benchmark_temporal --synthetic --report
artifacts/temporal-ollama-compact-benchmark-report.json` (одной строкой).
Реальный локальный Ollama `qwen2.5vl:3b`, RTX 4050 Laptop 6 GB, Windows,
Python 3.14.6. Legacy: один JPEG/2048 context; temporal: три JPEG/4096 context,
в обоих `num_predict=200`, max_vlm_calls=6. Порядок legacy → temporal,
без выгрузки модели; прогретость и кеширование могли различаться.

| Метрика | Legacy | Desk temporal |
| --- | ---: | ---: |
| Полное время, со spawn/cleanup | 18.752 s | 24.644 s |
| Decode / CV / JPEG I/O | 0.057 / 0.017 / 0.014 s | 0.241 / 0.047 / 0.040 s |
| Время VLM, включая подготовку/lock | 17.972 s | 23.322 s |
| Decoded всего | 140 | 267 |
| Decoded first / second pass | 140 / 0 | 140 / 127 |
| Overview / refined samples | 14 / 0 | 14 / 42 |
| Кандидаты до / после dedup | 3 / 3 | 6 / 2 |
| После refinement | нет | 2 |
| Длительности кандидатов | 3 × 6.0 s | 2 × 2.25 s |
| VLM-попытки / успешные JSON | 3 / 3 | 2 / 2 |
| Полные triplet | нет | 2 |
| Status / overview decoded coverage | complete / 100% | complete / 100% |
| Диагностические ошибки | нет | нет |
| Наблюдаемый пик VRAM устройства | 5326 MiB | 5326 MiB |
| Число GPU snapshots | 30 | 39 |

Legacy слил оба движения в 0.5–6.5 s отдельно для каждой ROI. Temporal уточнил
интервалы до 0.75–3.0 и 3.75–6.0 s, без трёх дубликатов на действие.
Refinement декодировал окна 0.75–3.25 и 3.75–6.25 s. Несмотря на меньшее число
запросов, три изображения делают temporal медленнее на этой сцене.
VRAM измерена периодическими nvidia-smi snapshots всего устройства, включая
посторонние процессы; это не расход только модели и не точный мгновенный пик.

Первый реальный запуск расширенной схемы дал **2/2 `vlm_output_truncated`** при
200 output tokens (legacy 18.854 s, temporal 24.820 s, temporal `partial`).
Исправление: temporal-схема требует `observations=[]`, промпт просит compact JSON;
лимит 200 не увеличивался. Повторный запуск в таблице дал 2/2 валидных ответа.
Ошибки не ремонтировались и не выдавались за успешный анализ. В других сценах
truncation/context overflow по-прежнему возможны и должны давать partial.

Отдельный CV-only прогон: legacy 0.785 s, temporal 1.002 s, 0 VLM-вызовов,
оба partial с ожидаемым `vlm_call_limit`; те же counts/интервалы. Он запускался
параллельно unit checks, поэтому не является изолированным CPU performance test.

Короткий импульс полностью пропущен обоими обзорными проходами и не попал в
выбранные refinement окна. Это воспроизводимый synthetic miss, покрытый тестом.
Даже статус complete и 100% decoded coverage не означают обнаружение всех действий.
Данные не дают precision/recall распознавания передачи наличных. Нет явного
локального пути к разрешённому банковскому MOV: `X-1.mov` не искался по диску.
Реальная калибровка Desk, банковское качество/скорость, длинные записи и YOLO
в этом этапе не проверены. Команда для разрешённого MOV — в [temporal guide](temporal.md).
JPEG/MOV и полные JSON остались в игнорируемом `artifacts/`, в Git их нет.

## Benchmark VLM

Команда: `python -m scripts.benchmark_vlm artifacts/synthetic-jpegs --repeats 5
--cold-start --report artifacts/cold-benchmark-report.json` (одной строкой).

Вход — **5 синтетических JPEG, 384×256**, пустой фон/простой красный прямоугольник,
пять повторений. Реальных банковских изображений не было. Один JPEG за запрос,
temperature 0, num_ctx 2048, num_predict 200. max_side 1024; маленькие изображения
не увеличиваются. Изображения повторяются: кеширование embeddings может ускорять
повторные запросы, поэтому это не оценка производительности на новых банковских кадрах.

Cold здесь означает отсутствие загруженной модели в /api/ps перед первым запросом.

только модели; пик зависит от частоты опроса. CPU allocation из /api/ps не означает
нулевую загрузку CPU. Содержимое JPEG, их названия и ответы VLM в benchmark JSON
не сохраняются. Локальный JSON находится в игнорируемом `artifacts/`.

Предыдущий тёплый прогон 10 запросов: среднее 2.192 с, медиана 1.949 с, 0 ошибок;
P95 не рассчитывался из-за размера выборки. Значения меняются с кешем и нагрузкой.
Шесть вызовов по измеренному тёплому среднему — около 11.3 с только VLM, без
декодирования, CV, незнакомых сцен и длинных видео. Гарантии 300 секунд нет.

## Контекст и temporal-вызов

Три JPEG при num_ctx=2048 отклонены Ollama: запрос потребовал 3270 токенов.
Те же настройки с num_ctx=4096 приняли 3 изображения: 13.039 с в отдельной проверке.
Это основание увеличить контекст именно для temporal-режима, не для всех запросов.
Начальный профиль использует один кадр и 2048; передача объекта по одному кадру
в итоговом CandidateEvent всегда unknown. Повторите benchmark на нужном разрешении:
для иной сцены 4096 тоже может не хватить. Превышение контекста — явная ошибка,
никаких скрытых успешных повторов или выдуманных наблюдений.

## Отрицательные controls и ограничения качества

Пять контрольных изображений не содержали людей, денег, телефонов, документов,
стекла или передачи объектов. Отдельный реальный прогон модели вернул:

| Признак | yes / no / unknown из 5 |
| --- | --- |
| people_visible | 0 / 5 / 0 |
| cash_visible | 0 / 5 / 0 |
| phone_visible | 0 / 5 / 0 |
| document_visible | 0 / 5 / 0 |
| reflection_possible | **5 / 0 / 0** |
| physical_presence после консервативной нормализации | 0 / 0 / 5 |

Пять ложных предположений об отражении — обнаруженное ограничение модели/промпта.
`reflection_possible=yes` является сигналом неопределённости, не подтверждением
отражения или нарушения; ReflectionGuard ограничивает утверждение о присутствии.
Этот маленький синтетический набор не измеряет precision/recall банковского кейса.
Нужно локально разметить реальные отрицательные сцены (стекло, тени, похожие вещи),
разделить tuning и validation, затем оценить false positives. Лиц и идентификации нет.
