# Проверки интеграции backend и vision

Установка из корня репозитория в отдельной виртуальной среде:

```powershell
python -m pip install -e ".[dev,backend]"
python -m pytest
ruff check .
ruff format --check .
git diff --check
```

Backend-зависимости объявлены отдельной optional-группой в pyproject.toml;
requirements.txt сохранен для существующего запуска backend/UI.
GitHub Actions устанавливает dev и backend для четырех комбинаций:
Ubuntu/Windows и Python 3.11/3.14.

Fixture backend-тестов использует отдельные SQLite и uploads в pytest tmp_path.
ML заменяется тестовой coroutine; HTTP-маршруты, очередь и SQLite остаются
настоящими. Тесты не читают банковские видео, не вызывают Ollama и не пишут
в рабочую data/jobs.db. Дополнительно проверяются обязательность upload-файла,
сохранение тестового содержимого и видимость ошибки записи.

CI-исправления сохраняют файлы и авторские заголовки участника №1. В Rule Engine
изменены форматирование и неиспользуемый импорт; AST условий, значений каталога
и объяснений совпадает с исходным main bd5164c. Shared contract и app/vision
не меняются. Два точечных исключения UP042 сохраняют прежнее поведение
str(member) у публичных Enum вместо несовместимого перехода на StrEnum.

Локально на Windows / Python 3.14.6: 159 passed, 2 skipped; Ruff и форматирование
прошли. Два пропуска — существующие opt-in тесты настоящего MOV/модели.
Установленный Starlette выдает предупреждение об устаревании httpx TestClient;
оно не подавляется и не приводит к ошибке тестов.

Зеленые технические проверки не подтверждают нормативные ссылки или юридические
выводы существующего движка/UI. Их содержание здесь не пересматривается;
исследование нормативных оснований находится в отдельном PR #5.
